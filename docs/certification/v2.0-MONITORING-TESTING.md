# TMS v2.0 System Health & Monitoring Testing Strategy

## 1. Health Aggregation
- [ ] **Data Accuracy**: Verify that the dashboard accurately reflects the state of the infrastructure (simulated via mock service in testing).
- [ ] **Integration Failures**: Simulate a third-party integration failure (e.g., M-Pesa) and verify the "Degraded" status appears in the UI.
- [ ] **DB Stats**: Verify that connection pool utilization and query performance metrics are correctly calculated.

## 2. Incident Management
- [ ] **Declaration Workflow**: Declare an incident and verify it creates a DB entry, audit log, and notifies relevant commanders.
- [ ] **Severity Escalation**: Change incident severity from SEV3 to SEV1 and verify the UI updates immediately.
- [ ] **Status Updates**: Add multiple updates to an incident and verify they are displayed in chronological order.
- [ ] **Resolution**: Mark an incident as RESOLVED and verify that `resolvedAt` is set and the duration is calculated correctly.

## 3. Alerts & Notifications
- [ ] **Trigger Logic**: Manually trigger an alert condition (e.g., set error rate threshold to 0.01%) and verify the alert state changes.
- [ ] **Channel Delivery**: Verify that alert notifications are sent via the configured channels (Mock SMTP/Slack/Webhook).

## 4. Log & Error Exploration
- [ ] **Axiom Connectivity**: Test the log search with various filters (level, service, message) and verify result accuracy.
- [ ] **Sentry Integration**: Verify that error trends and top recurring issues are pulled correctly from the Sentry API.

## 5. Security & RBAC
- [ ] **Read-Only Access**: Verify that "Support Admin" can see the health dashboard but cannot declare incidents or update alert rules.
- [ ] **Audit Completeness**: Verify that every action in the monitoring module (`INCIDENT_DECLARED`, `POSTMORTEM_PUBLISHED`) results in a detailed audit log entry.

## 6. Performance
- [ ] **Real-time Updates**: Verify that the dashboard remains responsive while handling simulated high-frequency log streams.
- [ ] **Query Efficiency**: Ensure that listing thousands of historical incidents remains efficient using pagination.
