# TMS v2.0 Super Admin Profile & Settings Testing Strategy

## 1. Profile Management
- [ ] **Data Persistence**: Update name and phone number, then verify changes in the database and across the UI.
- [ ] **Localization**: Change preferred language and time zone, ensuring they persist upon page reload.
- [ ] **Input Validation**: Attempt to save empty name or invalid phone formats (if validation is added).

## 2. Security & Authentication
- [ ] **Password Change**: Verify that changing password requires the correct old password.
- [ ] **Password Hashing**: Verify in the database that passwords are encrypted using bcrypt.
- [ ] **MFA Toggle**: Test the UI state for MFA and verify the underlying `mfaEnabled` flag in the `User` model.
- [ ] **Audit Trail**: Ensure `SUPER_ADMIN_PASSWORD_CHANGED` and `SUPER_ADMIN_PROFILE_UPDATED` actions are recorded in `AuditLog`.

## 3. Session Control
- [ ] **Session Visibility**: Verify that all active sessions for the current Super Admin are listed with correct IP and user agent.
- [ ] **Single Revocation**: Revoke a specific session and verify that the corresponding token is deleted from the `Session` table.
- [ ] **Global Revocation**: Test "Revoke All Other Sessions" and ensure only the current session remains.

## 4. API Token Lifecycle
- [ ] **Token Generation**: Create a new token and verify it is displayed exactly once.
- [ ] **Hashed Storage**: Verify that the token secret is stored as a SHA-256 hash in the `SuperAdminApiToken` table.
- [ ] **Revocation**: Revoke a token and ensure it can no longer be used for API authentication (integration test with an API endpoint).
- [ ] **Audit Logs**: Verify that token creation and revocation are recorded.

## 5. Notification Preferences
- [ ] **Channel Toggles**: Toggle Email, SMS, and In-App channels and verify persistence.
- [ ] **Category Toggles**: Enable/Disable specific categories like "Security Alerts" and verify that the `NotificationPreference` record is updated correctly.

## 6. Access Control (RBAC)
- [ ] **Self-Service Only**: Verify that a Super Admin can only access and modify their own profile and settings.
- [ ] **Permission Enforcement**: Ensure non-Super Admin users cannot access the `/admin/settings/*` routes or call the corresponding server actions.

## 7. UI/UX
- [ ] **Responsive Design**: Test all settings pages on mobile and tablet breakpoints.
- [ ] **Loading States**: Verify that save buttons show loading indicators during server action execution.
- [ ] **Error Handling**: Verify that toast notifications appear for failed password changes or network errors.
