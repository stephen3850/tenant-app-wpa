# TMS v2.0 Integrations & Jobs Module Testing Strategy

## 1. Security & Configuration
- [ ] **Secret Encryption**: Verify that `apiKey`, `consumerSecret`, etc., are stored encrypted in the `config` JSON field.
- [ ] **Decryption**: Ensure that provider SDKs can successfully decrypt and use the stored secrets.
- [ ] **Least Privilege**: Verify that only users with `SUPER_ADMIN` role can view or manage integrations.

## 2. Job Lifecycle
- [ ] **Job Creation**: Manually trigger a job (e.g., via a test action) and verify it appears in the Jobs Center as `QUEUED`.
- [ ] **Processing**: Verify status transition from `QUEUED` -> `PROCESSING` -> `COMPLETED`.
- [ ] **Retries**: Force a job failure and verify that the `Retry` button correctly increments `attempts` and sets status to `RETRYING`.
- [ ] **Idempotency**: Ensure that multiple retries of the same job do not result in duplicate side effects (e.g., duplicate M-Pesa STK pushes).

## 3. Webhooks
- [ ] **Signature Validation**: Test incoming webhooks with valid and invalid signatures.
- [ ] **Payload Logging**: Verify that webhook payloads are logged in `PlatformWebhookDelivery`.
- [ ] **Replay**: Test the "Replay Webhook" functionality and ensure it correctly re-processes the original payload.

## 4. Scheduled Tasks
- [ ] **Cron Evaluation**: Verify that `nextRunAt` is correctly calculated based on the cron expression.
- [ ] **Task Execution**: Verify that tasks execute at the scheduled time (simulated via `systemDb` update).

## 5. Audit Accuracy
- [ ] **Action Tracking**: Verify that all actions (`INTEGRATION_ENABLED`, `SECRET_ROTATED`, `JOB_RETRIED`) create an entry in the `AuditLog`.
- [ ] **Platform Logs**: Ensure audit logs for these actions have `organizationId: null` or `"SYSTEM"`.

## 6. Performance
- [ ] **Large Datasets**: Verify that the Jobs Center remains responsive with >10,000 job entries (use pagination).
- [ ] **Concurrent Jobs**: Test system behavior under high concurrency using QStash fan-out simulations.
